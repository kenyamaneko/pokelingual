# pokelingual テスト固有ルール (overlay)

## [pokelingual] テストデータ

- 共通ルールの「本番の実データ ID をそのまま使わない」は本リポでは適用しない。図鑑番号・名前・タイプ・種族値・説明文を含め、公開済みのポケモンデータはゲームの仕様として後から変わることが実質的に無いため、テストでも実データをそのまま使ってよい

## [pokelingual] テスト名とテスト観点カタログ

keyandnotes-rules へ修正案を出している途中のため、共通ルール「テストの命名」のうち次の事項は、本リポでは次のとおり書き換えて適用する。共通ルールが同じ内容に改まったら、この節の該当部分を削除する。

- テスト名は `[区分:大機能(:中機能)]小機能` > ケース の階層にする。種別と正常異常は階層の段にしない
  - `[区分:大機能(:中機能)]小機能` = 最も外側の `describe`。中機能は任意で、運用では置かない
  - ケース = テスト用の補助関数 `defineCase` の呼び出し。引数は、種別・正常異常・ステップと、検証の本体。Vitest 用 (backend・frontend) と Playwright 用 (E2E) がある。テスト名を直接書かない
- ケースは 1 つ以上のステップを持つ。ステップは Given (任意)・When (必須。1 つ以上の操作を実行する順に並べる。1 つの操作は「〜する」の形)・Then (必須) からなる
  - 前提が無いとき、または直前のステップの結果の状態が前提のときは、Given を省略する
  - Given は、状態を表す形で書く (「〜しているとき」「〜されているとき」「〜であるとき」「〜のとき」)。出来事は When に書く
  - When の各操作は、どの画面 (画面が無いときは、どの API や処理) の、どの機能に対して、何をするかが読み取れるよう書く。画面名と機能名 (小機能の名前に使う語) を含める。内部の処理を確かめるテストでも、その処理が使われる画面と機能の言葉で書く
  - ステップを複数にするのは、シナリオテストと、異常からの回復の確認 (失敗、再試行、成功) だけ。操作のたびに結果を確認するテストは、確認ごとにステップを分ける。操作を続けて行い、途中で確認しないときは、1 ステップの中の複数の操作にする
  - ケースの項目 (種別・正常異常・Given・When・Then) は、`defineCase` がテスト結果に注釈として載せる。カタログ生成は、この注釈を読む
- 共通の前提・共通の操作はテストに書かない。Given・When は、ケースごとに同じ文で書く。カタログが、同じ値が続く行を表のセルにまとめる
- 区分は 本体・外部連携・運用・シナリオ。シナリオテストは複数の機能をまたぐため、区分を「シナリオ」とし、大機能は利用者の目的、中機能は動線の種類、小機能は動線の始点と終点にする
- 大機能と中機能は、カタログ生成が読む一覧にある組だけを使う。一覧にない組を使うと、カタログ生成がエラーにする。追加が必要なときは、ユーザーに提案する
  - 大機能は、利用者が目的を達成する単位にする。画面・API・内部の部品の違いで分けない
  - 中機能は、ケースの Given・When・Then から判断できるときだけ付ける。判断できないときは付けない
- カタログは、区分・大機能・小機能の順に見出しの入れ子を作り、小機能ごとに Given・When・Then・タグの表を置く。中機能は見出しにしない。種別と正常異常で絞り込める

## [pokelingual] 大機能と中機能の一覧

大機能と中機能は、次の一覧にある組だけを使う。カタログ生成が読む一覧にも、同じ内容を反映する。

- 区分「本体」の大機能: チュートリアル・クエスト・名前当て・採点・捕獲・図鑑・AI 呼び出し回数
- 区分「共通」の大機能: 認証・設定・サイト情報・画面共通・機能共通
  - 画面共通: ヘッダー・404 画面など、複数の大機能が使う画面や画面の部品
  - 機能共通: ポケモンデータ・ポケモンのタイプの表示・乱数による抽選など、複数の大機能が使う処理
- 区分「運用」の大機能: ログ出力・起動と設定。中機能は置かない
- 区分「外部連携」の大機能: AI・ポケモンデータ提供元
- 区分「シナリオ」の大機能: ポケモンを捕まえる・捕まえたポケモンを図鑑で確かめる・チュートリアルを終えてクエストを始める
- 中機能 (本体・共通): 画面表示・演出・入力・操作・画面遷移・一連の操作・要求の送信・受付・業務ルール・業務処理・保存と取得・状態の維持
- 中機能 (外部連携): 応答の変換・失敗と再試行・データの取り込み
- 中機能 (シナリオ): 通常の動線・異常から回復して目的を達成する動線・最終的にエラーになる動線・利用者設定を挟む動線
